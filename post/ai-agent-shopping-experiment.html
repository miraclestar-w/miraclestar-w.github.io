给AI Agent一张信用卡，5小时它能花出去吗

2026-06-01 · AI, Agent, 电子商务, 自动化

波兰开发者 Paweł Józefiak 做了一个简单到极致的实验：给他的 AI Agent 一张 25 美元的虚拟借记卡，让它去网上买一个礼物。不限商品，不限商店，唯一的要求是——把钱花出去。

五小时后，Agent 逛了四家店，尝试了各种手段。结果：0 笔成交，0 美元花出去。

这听起来像个笑话，但它揭示了一个严肃的事实——整个互联网的商业基础设施，从诞生那天起就不是为 Agent 设计的。

实验过程：从自信到崩溃

第一站：Allegro（波兰最大电商）

Agent 打开 Allegro 首页，几乎在毫秒级别就被 Cloudflare 拦截了。Cloudflare 的 Bot Detection 不需要看任何内容——浏览器指纹、JavaScript 执行环境、鼠标轨迹，任何一个特征不匹配就直接拒绝。

这里有一个技术细节值得注意：Cloudflare 不是检测到"这个浏览器在自动化操作"，而是检测到"这个浏览器不是正常的浏览器"。无头 Chrome 再怎么伪装，它的 JavaScript 运行时环境和真实 Chrome 存在可测量的差异。就像一个人可以穿西装打领带走进商务场合，但走路的姿势、拿杯子的方式、眼神的聚焦点，都会在 3 秒内暴露他不常来。

第二站：Amazon.pl（登录墙）

Allegro 被封，Agent 转向 Amazon。这回它甚至没来得及看到商品列表——必须登录。Agent 尝试通过 Apple Keychain 读取保存的密码，失败。即使在 macOS 上以 root 权限运行，Keychain 的密码仍然存储在硬件安全模块（Secure Enclave）中，进程隔离保证了任何应用都无法直接读取。

这层防御的精妙之处在于：它不依赖软件层面的检测，而是依赖硬件层面的隔离。你没有 root 权限的问题，你有的是"密码根本不在你能接触到的地方"。

第三站：Empik（两次尝试）

Empik 是第一次尝试用无头浏览器进入的。Cloudflare Turnstile 专门针对无头浏览器做了特征检测，直接拦截。

Paweł 放弃了无头浏览器，换成真实的 Safari，让 Agent 通过真正的浏览器界面操作。这次成功了——Agent 找到了商品、填了地址、选了配送方式。一切顺利，直到支付环节。

支付页面用了一个 P24（波兰主流支付网关）的 iframe。Agent 尝试与 iframe 内的元素交互，但 CORS（跨源资源共享）策略阻止了一切——iframe 内的支付表单和外部页面属于不同源，浏览器的安全沙箱切断了任何跨源操作的可能。

Agent 在这一步卡死。它可以浏览、选择、填写一切，但最后 3 厘米的距离——点击"确认支付"——它永远够不到。

五层防御体系：不是设计出来的，是长出来的

这个实验最有趣的地方在于：没有任何一家公司专门为了阻止 AI Agent 购物而设计了这些机制。每一层防御都是在某个时间点为了某个其他目的被引入的：

第一层：Bot 检测（Cloudflare/Turnstile）—— 最初是为了防爬虫和 DDoS 攻击。在 2020 年代初被大量部署，到 2024 年已经成为网站标配。

第二层：认证墙（强制登录）—— 最初是为了用户追踪和个性化推荐。但当 Agent 不在浏览器的 Cookie 体系内时，它就成了不可逾越的障碍。

第三层：CAPTCHA（验证码）—— 最初是为了区分人和机器。现在 Cloudflare Turnstile 甚至不需要用户手动操作，它通过浏览器环境分析来判断，这对 Agent 来说是不可破解的——你不能"表现得更像人"，因为你的操作系统就不是人。

第四层：浏览器指纹（Fingerprint）—— 最初是广告追踪技术，用于在不依赖 Cookie 的情况下识别用户。但它同时也成为检测自动化工具的利器。

第五层：支付隔离（iframe + CORS）—— 最初是为了安全——防止恶意脚本窃取支付信息。但在 Agent 时代，它也阻止了合法的自动化操作。

这五层防御各自独立，却在 Agent 面前形成了一道无法突破的墙。每多加一层安全措施，就多堵上一个 Agent 可能的突破口。

正在到来的解决方案

好消息是，电商巨头们已经开始正视这个问题。2025-2026 年间，几个关键基础设施正在被搭建：

Shopify Agentic Storefronts

Shopify 在 2025 年 10 月宣布了 Agentic Storefronts 概念，2026 冬季正式上线。核心变化：

  • 每个 Shopify 店铺都会有一个 MCP（Model Context Protocol）端点
  • 产品信息直接同步到 ChatGPT、Perplexity、Copilot 等 AI 平台
  • Agent 可以通过 API 完成浏览、选择、下单、支付全流程
  • Shopify 自己的数据显示，AI 渠道带来的流量增长了 7 倍

Stripe Agentic Commerce Suite

Stripe 在 2025 年 12 月发布了 Agentic Commerce Suite，提供 API 化的产品发现、结账和支付能力。简单说：Stripe 把"人点击按钮"的流程抽象成了"Agent 调用接口"。

Universal Commerce Protocol (UCP)

Google 和 Shopify 联合开发的通用商务协议，已有 20+ 零售商支持。目标是让 AI 助手能在不同零售商之间无缝比较和购买。

WooCommerce 10.3

开源电商系统 WooCommerce 也加入了，2025 年 11 月宣布支持 MCP。这意味着独立站也能被 Agent 访问。

真正的商业机会在哪里

回到"AI Agent 赚钱"这个话题。Paweł 的实验告诉我们一个残酷的现实：Agent 现在连"花别人的钱"都做不到，更别说"赚自己的钱"了。

但这恰恰是机会所在。

能被 Agent 直接访问的商业基础设施（API、MCP 端点、结构化数据）目前极度稀缺。这意味着：

  • 谁先把服务暴露为 Agent 可调用的 API，谁就能在 Agent 经济中获得先发优势
  • 谁开发了连接 Agent 和传统电商的中间层（比如自动填表、自动支付），谁就抓住了基础设施级别的机会
  • 谁的垂直领域数据结构化程度最高，谁就是 Agent 首选的信息源和交易入口

Shopify 已经在行动了——它的 AI 流量增长 7 倍不是因为 Agent 变聪明了，而是因为它主动把自己变成了 Agent 能访问的形状。

我的实验计划

读完 Paweł 的实验，我想做一个自己的版本。不是去测试"Agent 能不能购物"（他已经证明了不能），而是测试一个更实际的问题：

一个 AI Agent 在当前条件下，到底能通过什么方式赚到第一块钱？

我的初步方向：

  • 写代码卖——用 Agent 生成开源工具，通过 GitHub Sponsors 或付费功能变现
  • 自动化服务——帮人做数据清洗、格式转换、API 集成这类重复性工作
  • 信息差——监控价格波动、套利机会，自动执行交易

但核心约束不变：Agent 必须在现有的互联网基础设施内工作。我们不能假设所有平台都会变成 Agent-friendly——在可预见的未来，大多数网站仍然会把 Agent 当作机器人来防御。

写在最后

Paweł 实验的真正价值不在于"Agent 花不出去钱"这个结果，而在于它暴露了一个结构性问题：互联网的 25 年安全进化，无意中创造了一个 Agent 无法生存的环境。

每一层为人类设计的安全措施，在 Agent 面前都变成了不可逾越的墙。Web 是为人类点击按钮设计的，不是为 API 调用设计的。

好消息是，Shopify、Stripe、Google 已经在修建"Agent 专用通道"。坏消息是，这条通道还很窄，而且优先服务大商家。

对于独立开发者和小团队来说，真正的问题不是"Agent 能不能购物"，而是"在 Agent 能购物的基础设施就绪之前，我能做什么来卡位"。

这可能是 2026 年最值得关注的基础设施赛道之一。
