Docker容器化部署指南

2026-05-26 · Docker, 容器化, DevOps, 部署, 微服务

Docker容器化已经成为现代应用部署的标准方式。它将应用及其依赖打包在一个轻量级、可移植的容器中，实现了"一次构建，到处运行"。本文将从Dockerfile编写、多阶段构建、Docker Compose编排到生产环境加固，全面介绍容器化部署的最佳实践。

Dockerfile编写最佳实践

选择合适的基础镜像

基础镜像的选择直接影响镜像大小和安全性：

  • Alpine：仅5MB，适合轻量级应用
  • Distroless：Google出品，无shell无包管理器，安全性最佳
  • Ubuntu/Debian：兼容性最好，但镜像较大
# 反例：不推荐的写法
FROM ubuntu:latest
RUN apt-get update && apt-get install -y python3 python3-pip
COPY . /app
RUN pip3 install -r requirements.txt
CMD ["python3", "app.py"]

# 正例：推荐的写法
FROM python:3.12-slim AS base
WORKDIR /app

# 利用缓存层，先复制依赖文件
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 再复制源代码
COPY . .

# 使用非root用户运行
RUN useradd -r -s /bin/false appuser
USER appuser

EXPOSE 8000
CMD ["python", "app.py"]

利用构建缓存

Docker逐层构建镜像，理解缓存机制可以显著加速构建过程：

  1. 将变化频率低的指令放在前面（如安装依赖）
  2. 将变化频率高的指令放在后面（如复制源代码）
  3. 使用.dockerignore排除不需要的文件
# .dockerignore
node_modules
.git
.env
*.md
dist/
coverage/
.nyc_output/
Dockerfile
docker-compose*.yml

多阶段构建

多阶段构建是控制镜像大小的关键技术。将编译环境和运行环境分离，最终镜像只包含运行时必需的文件。

Go应用示例

# 构建阶段：使用完整的Go工具链
FROM golang:1.22-alpine AS builder
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o /app ./cmd/server

# 运行阶段：使用极简的scratch镜像
FROM scratch
COPY --from=builder /app /app
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
EXPOSE 8080
ENTRYPOINT ["/app"]

Node.js应用示例

# 构建阶段
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
RUN npm run build

# 运行阶段
FROM node:20-alpine
WORKDIR /app
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./

USER appuser
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=3s CMD wget --quiet --tries=1 --spider http://localhost:3000/health || exit 1
CMD ["node", "dist/index.js"]

Docker Compose服务编排

对于多服务应用，Docker Compose是最便捷的编排工具：

# docker-compose.yml
version: '3.8'

services:
  # Nginx反向代理
  nginx:
    image: nginx:alpine
    container_name: nginx-proxy
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - ./nginx/ssl:/etc/nginx/ssl:ro
    depends_on:
      app:
        condition: service_healthy
    restart: unless-stopped
    deploy:
      resources:
        limits:
          cpus: '0.50'
          memory: 256M

  # 应用服务
  app:
    build:
      context: .
      dockerfile: Dockerfile
      target: production
    container_name: web-app
    env_file:
      - .env
    expose:
      - "3000"
    volumes:
      - app_data:/app/data
    healthcheck:
      test: ["CMD", "wget", "--quiet", "--tries=1", "--spider", "http://localhost:3000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
    restart: unless-stopped
    deploy:
      replicas: 2
      resources:
        limits:
          cpus: '1.00'
          memory: 512M

  # Redis缓存
  redis:
    image: redis:7-alpine
    container_name: redis-cache
    command: redis-server --appendonly yes --maxmemory 256mb --maxmemory-policy allkeys-lru
    volumes:
      - redis_data:/data
    restart: unless-stopped
    deploy:
      resources:
        limits:
          cpus: '0.25'
          memory: 256M

  # PostgreSQL数据库
  postgres:
    image: postgres:16-alpine
    container_name: postgres-db
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - pg_data:/var/lib/postgresql/data
      - ./db/init:/docker-entrypoint-initdb.d
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER}"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: unless-stopped
    deploy:
      resources:
        limits:
          cpus: '1.00'
          memory: 1G

volumes:
  app_data:
  redis_data:
  pg_data:

生产环境安全加固

镜像安全

  • 扫描漏洞：使用 trivy image 或 docker scout 扫描镜像
  • 固定版本：永远使用具体版本标签，避免使用 latest
  • 最小权限：不在容器中运行root用户
  • 签名验证：启用Docker Content Trust进行镜像签名
# 镜像安全扫描
trivy image --severity HIGH,CRITICAL myapp:latest

# Docker Content Trust
export DOCKER_CONTENT_TRUST=1
docker push myregistry/myapp:v1.0

运行时安全

  • 只读文件系统：使用 --read-only 挂载容器
  • 资源限制：设置CPU和内存上限
  • 网络隔离：使用自定义网络，限制容器间通信
  • Seccomp/AppArmor：启用系统调用过滤
# 安全运行示例
docker run \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid \
  --cap-drop ALL \
  --cap-add NET_BIND_SERVICE \
  --security-opt no-new-privileges \
  --memory 256m \
  --cpus 0.5 \
  --pids-limit 100 \
  myapp:latest

容器日志与监控

生产环境中，容器的日志和监控同样重要：

  • 日志驱动：配置 json-file 或 fluentd 驱动
  • 日志轮转：设置 max-size 和 max-file 防止磁盘撑满
  • cAdvisor：实时监控容器资源使用
  • Prometheus：采集容器和应用指标
# daemon.json 配置日志驱动
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}

CI/CD集成

将Docker构建集成到CI/CD流水线中，实现自动化部署：

# GitHub Actions 示例
name: Build and Deploy
on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          push: true
          tags: |
            ghcr.io/${{ github.repository }}:latest
            ghcr.io/${{ github.repository }}:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

      - name: Deploy to server
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_KEY }}
          script: |
            docker pull ghcr.io/${{ github.repository }}:${{ github.sha }}
            docker-compose up -d --force-recreate

总结

Docker容器化部署的核心原则是：安全、轻量、可复现。通过合理选择基础镜像、利用多阶段构建、实施安全加固和集成CI/CD流水线，可以构建出高效、可靠的容器化部署体系。

容器化不仅是技术的变革，更是运维理念的升级——它推动团队从传统的"服务器运维"转向"基础设施即代码"的现代化运维模式。
